# Memory Button — Архитектура (MVP)

## Назначение
Бэкенд для Android-приложения «Memory Button» — голосовые воспоминания о предках.  
Один пользователь / одна семья. Диалог с ИИ строго по очереди (user → обработка → assistant).

## Компоненты
- **HTTP API (Go, REST, `/api/v1`)** — аутентификация, CRUD людей/связей/вопросов, сессии turn-by-turn, подтверждение черновиков, Q&A, медиа.
- **PostgreSQL** — основное хранилище (люди, связи, сессии/реплики, рассказы, факты, реестр вопросов, черновики/draft_items, outbox jobs, метаданные медиа). Миграции применяются при старте.
- **Object storage (S3-compatible / MinIO или FS)** — аудио и фото (`STORAGE_DRIVER=s3|fs`).
- **AI-провайдер (HF / stub)** — ASR (распознавание), LLM (интервьюер/экстрактор/Q&A), TTS (синтез). При недоступности HF — graceful fallback на заглушки с пометкой `fallback`.
- **Воркер (outbox в PostgreSQL)** — постобработка завершённых сессий в черновик (асинхронно) либо синхронно (`PROCESSING_SYNC=true`).

## Потоки данных

### Диалог (turn-by-turn)
1. `POST /sessions` — создание сессии (`new_story|continue_person|clarify_person|qa`), стартовая реплика помощника с контекстом (что известно, открытые вопросы).
2. `POST /sessions/{id}/turns` (multipart audio) — сохранение аудио → ASR → ответ LLM с учётом режима/персоны/сводки/фактов/вопросов → TTS → сохранение реплик, возврат текста и аудио.
3. `POST /sessions/{id}/complete` — завершение и запуск постобработки.

### Постобработка и подтверждение (критично)
- Экстрактор формирует **черновик** (`drafts`, `draft_items`): связный рассказ, предлагаемые люди/связи/факты/вопросы. В основные таблицы ничего не пишется автоматически.
- `GET /sessions/{id}/draft` — клиент показывает черновик.
- `POST /drafts/{session_id}/confirm` — рассказчик подтверждает/отклоняет/правит пункты. **Только подтверждённое** атомарно применяется в транзакции (создание/связи/факты/вопросы/подтверждённый рассказ). ИИ не меняет дерево/связи молча.

### Q&A
- `POST /qa/ask` — поиск по **подтверждённым** фактам и рассказам, ответ LLM строго по контексту, возврат `sources[]`.
- При нехватке данных — `insufficient_data=true`, честный ответ и `suggested_questions` (в т.ч. из реестра).

## Модель данных (основное)
- `persons`, `relationships` — древо/карточки (варианты ФИО, approx-даты, фото, заметки).
- `sessions`, `turns`, `transcripts` — диалоги.
- `stories`, `facts` — подтверждённые рассказы и факты (с источниками/фрагментами).
- `questions` — реестр (`open|resolved|dismissed`, общий или по person_id).
- `drafts`, `draft_items` — предложения ИИ до подтверждения.
- `media` — метаданные файлов в object storage.
- `jobs` — outbox фоновых задач.

## Безопасность и эксплуатация
- Single-user: bcrypt + JWT HS256, опциональный статический bearer для отладки.
- Секреты и ключи HF/S3 — через env, не в коде.
- Рекомендуется запуск за TLS/reverse-proxy; чувствительный контент не логируется целиком.
- Загрузки ограничены по размеру; дубли вопросов подавляются уникальным индексом.

## Развёртывание
- Docker Compose (api + postgres + storage) или бинарник + внешние зависимости.
- Swagger/OpenAPI: `/docs/`, `/openapi.yaml` (см. `docs/openapi.yaml`).
- Публичный инстанс (MVP): `https://<host>:8451` (nginx → 127.0.0.1:8094), health: `/health`.
